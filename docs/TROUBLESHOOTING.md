# 印字トラブル対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 接続テストがタイムアウト | IP 違い / 別セグメント / 電源 | `設定 → LAN を探す` で 9100 番が開いているホストを探す。プリンタの自己診断印刷（フィードボタン長押しで起動）に IP が出る機種が多い |
| 途中で印字が切れる | 受信バッファ溢れ | `分割行数` を 128 → 64 → 32 と下げる |
| 右端に黒い帯が出る | ラスタのパディング処理不備 | 本アプリでは対策済み（[PROTOCOL.md](PROTOCOL.md) 参照）。自作ツールを併用している場合はそちら側を確認 |
| 横幅が合わない / 右が欠ける | 用紙幅の設定違い | 203dpi なら 58mm=384dot、80mm=576dot。576 で欠けるなら 512 を試す |
| 文字化け・□ になる | フォント未検出 | `設定 → フォント` で日本語 TTF/TTC を明示指定（Win: `meiryo.ttc`、Mac: ヒラギノ） |
| 全体に薄い / 潰れる | 二値化方式が不適 | 文字中心なら「しきい値」、写真なら「ディザ」、影のある紙の写真なら「適応的」。コントラストも上げる |
| カットされない | カット非対応機 or 別コマンド | `印刷後にカット` を OFF にして `カット前フィード` を増やし、手切りに |
| 印刷はされるが履歴に残らない | 履歴が OFF | `設定 → 印刷履歴を残す` を確認 |
| 同期フォルダに出ない | 自動書き出しが OFF / パス不正 | `設定 → 同期フォルダへ自動書き出し` にチェックし、フォルダを選び直す。`履歴 → 全件を書き出し` で一括再出力できる |

## 切り分けの順序

```bash
python -m thermal_memo test          # 1. TCP は通るか（紙を使わない）
python -m thermal_memo test-page     # 2. 実際に印字されるか
python tools/fake_printer.py         # 3. アプリ側の出力が正しいか（PNG で確認）
```

3 の PNG が正しいのに実機で崩れる場合はプリンタ側（幅・バッファ・機種差）、
PNG の時点で崩れているならレンダリング設定（フォント・二値化・用紙幅）が原因。
