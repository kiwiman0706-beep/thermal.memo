# 送信している ESC/POS の仕様

`thermal_memo/escpos.py` が生成するバイト列の定義。実装を移植するときはここを参照。

## 全体の流れ

印刷対象（テキスト・スクショ・PDF ページ）は**すべて 1bit 画像に変換してから**
ラスタ画像として送信する。プリンタ内蔵フォントは一切使わない。

```
ESC @                     プリンタ初期化
GS  L 0 0                 左マージン 0
ESC a n                   位置揃え（0=左 / 1=中央）
  ├ GS v 0 …              ラスタバンド（chunk_rows 行ずつ、必要な回数）
  ├ ESC d n               n 行フィード
  └ GS V 66 0             パーシャルカット（設定で省略可）
                          ← 部数ぶん繰り返し
```

## GS v 0（ラスタビットイメージ）

```
1D 76 30 m xL xH yL yH d1…dk
```

| フィールド | 値 |
| --- | --- |
| `m` | `0x00`（等倍） |
| `xL xH` | 1 行あたりのバイト数 = `ceil(width / 8)`、リトルエンディアン |
| `yL yH` | この命令で送る行数、リトルエンディアン |
| `d1…dk` | `xL xH` × `yL yH` バイトのビットマップ。**ビット 1 = 黒（印字）**、MSB が左端 |

### 分割送信

一度に数千行を送ると受信バッファが溢れて途中で切れる機種があるため、
既定で 128 行ごとに `GS v 0` を分けて送る（設定 `chunk_rows`）。
バンドは連続して送るので、紙の上では 1 枚の画像として繋がる。

### ビットの詰め方（実装上の注意）

Pillow の mode `"1"` は **1 = 白**、かつ各行がバイト境界までパディングされる。
そのため `tobytes()` の結果を全ビット反転して 1 = 黒 に直すが、
**行末のパディングビットまで反転すると右端に黒帯が出る**。
各行の最終バイトに `0xFF << (bytes_per_row * 8 - width)` のマスクを掛けて白へ戻すこと。

```python
spare = bytes_per_row * 8 - width
tail_mask = 0xFF if spare == 0 else (0xFF << spare) & 0xFF
row_bytes[-1] &= tail_mask
```

（この挙動は `tests/test_core.py::TestEscpos::test_pack_masks_row_padding` で検証している）

## その他のコマンド

| 用途 | バイト列 |
| --- | --- |
| 初期化 | `1B 40` |
| 左マージン 0 | `1D 4C 00 00` |
| 左寄せ / 中央寄せ | `1B 61 00` / `1B 61 01` |
| n 行フィード | `1B 64 n`（n = 0–255） |
| パーシャルカット（送り後） | `1D 56 42 00` |

## 用紙幅と印字ドット数（203dpi）

| 用紙 | 印字幅 |
| --- | --- |
| 58mm | 384 dot |
| 80mm | 576 dot（機種により 512） |
| 112mm | 832 dot |

`8 dot ≒ 1mm` なので、画像の高さ ÷ 8 がおおよその紙の長さ（mm）になる。

## 通信

- TCP、既定ポート **9100**（RAW / JetDirect）
- 送信後すぐ `close()` するとバッファを捨てる機種があるため 0.2 秒待ってから閉じる
- ステータス問い合わせ（`DLE EOT n`）は機種差が大きいため使用していない。
  疎通確認は TCP 接続の可否のみで判定する
